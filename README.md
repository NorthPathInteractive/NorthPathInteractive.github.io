# North Path Interactive

Games, music, comics and experiments published at https://northpathinteractive.github.io/.

## Publishing standard

This is the standing rule for all work published to North Path Interactive, including projects hosted in other repositories and linked from this site.

- Record every published change in a changelog. For project changes, use that project's CHANGELOG.md; for shared site changes, use the root CHANGELOG.md.
- For each shipped project version, add a dated entry with its version and concise player-facing Added, Changed, or Fixed notes as appropriate, newest first.
- Update the changelog in the same commit as the shipped changes. For a project hosted elsewhere, keep its authoritative changelog there and link to it from this site.
- Keep displayed versions consistent across the project, README, catalogue data, homepage card and project page where applicable. Increase the version for shipped software changes; documentation-only or shared-site changes can use a dated changelog entry without inventing a project version.
- Give every published project a direct, descriptive link to its authoritative changelog on its North Path project description page. Keep a short What's New summary there.
- Link version entries to their original code commits when known. For milestone releases, GitHub Releases and tags may supplement the changelog.
- Describe work that actually shipped. Keep plans separate, distinguish a successful push from a live deployment, and verify the live version and changelog link before reporting them live.
- Preserve existing history. When reconstructing older entries, verify changes and dates from repository evidence; label uncertainty rather than guessing.

## Current rollout

Dungeon 21 is the pilot: [project page](https://northpathinteractive.github.io/projects/dungeon-21/) and [changelog](dungeon-21/CHANGELOG.md).

Historical reconstruction, bulk version changes, and changelog backfills for other projects are on hold pending Steve's review of Dungeon 21. Apply the publishing standard to future authorized work; this instruction does not authorize a retrospective audit or publication of unrelated changes.
